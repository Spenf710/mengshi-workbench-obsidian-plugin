# 会话知识收割 Skill

> AI 读取本文件后，应能按标准化流程执行会话知识收割。本文件仅含可执行指令。

**触发条件**：用户说"总结对话""更新项目文件""归档对话""收尾""把今天聊的记下来""收割"
**不触发**：用户说"优化日志""写日志"时走 `work-log-refine`（如已安装）

---

## 一、标准化流程（5 步）

### Step 1 — 扫描对话轮次
回顾当前会话全部轮次，提取：
- 讨论过的**主题/项目**（按项目名归纳）
- 做出的**决策**（选型、方案定论）
- 产出的**具体内容**（代码、配置、分析报告）
- 有价值的**洞察**（踩坑经验、方法论提炼）

### Step 2 — 主题分类
按归属将每个主题映射到知识库目录：

| 主题类型 | 目标目录 | 判断依据 |
|----------|----------|----------|
| 归属已有项目 | `<你的项目目录>/<项目名>/` | 讨论中明确提到项目名 |
| 跨项目通用知识 | `<你的笔记分类目录>/` | 方法论、工具技巧、可复用经验 |
| 新项目雏形 | 暂不建目录 | 先记入通用笔记，标记 `#待立项` |

**示例**（替换为你自己的结构）：
```
项目管理/        ← 你的项目根目录
原子笔记/        ← 你的通用知识目录
```

### Step 3 — 逐主题处理（核心判断）

对每个主题执行以下判断：

```
已有对应文件？
├─ 是
│   ├─ 同等含义（补充细节/深化理解/追加数据）
│   │   → 追加到已有文件末尾（新 ## 章节 或 列表项追加）
│   └─ 不同含义（新角度/矛盾观点/独立话题）
│       → 新建独立文件，命名体现差异
└─ 否
    → 新建文件
        ├─ 归属项目 → 项目目录下，按你的命名规范命名
        └─ 通用知识 → 通用笔记目录，中文描述性命名
```

**追加方式**：
- 项目开发日志类 → 在文件末尾追加 `### YYYY-MM-DD 会话记录` 章节
- 方案/设计文档类 → 追加新的 `## 新话题` 章节
- 纯列表类（如索引）→ 在列表末尾追加条目
- **绝不覆盖或修改已有手写内容**

### Step 4 — 更新索引

- **项目 README**：新增文档追加到文档索引表；状态/里程碑变化更新核心信息表
- **通用笔记**：新建笔记加 YAML frontmatter（如 `tags`）+ 结尾 `**相关笔记：**` 区块

### Step 5 — 输出变更摘要

```
## 会话归档完成

### 📝 更新文件
- [[路径/文件名]] — 补充了XXX

### 🆕 新建文件
- [[路径/新文件名]] — 记录了XXX

### 📊 README 更新
- [[项目名.README]] — 文档索引追加 / 状态更新
```

---

## 二、关键约束

1. **不覆盖手写内容** — 追加而非替换，所有原有内容保持不动
2. **新建文件优先归类** — 能归入已有目录的不新建顶层目录
3. **不确定时询问** — 文件归属模糊或"同义/异义"难以判断时，列出选项让用户选
4. **不修改 YAML frontmatter** — 除非新建文件必须写入（`tags` 等）
5. **文件命名** — 中文描述性名称，避免纯粹日期前缀（日期信息放正文或 frontmatter 内）

---

## 三、场景速查

### 纯开发会话（写代码为主）
→ 更新项目 `开发日志.md`，追加当日会话记录

### 方案讨论会话（设计/架构/选型）
→ 方案定论追加到已有方案文档；新思路独立新建文件；跨项目方法论 → 通用笔记

### 知识库整理会话（笔记/工作流）
→ 沉淀到通用笔记对应分类

### 混合会话（多项目/多主题）
→ 逐主题独立处理，每个主题执行 Step 3 判断
